# Otter v2 개발용 설치 패키지

상태: 패키지 생성 경로와 내용 검사를 구현했다. Linux x64 앱 폴더 생성/정적 검사 및
Electron Node 모드에서 실제 ASAR 실행부의 HTTP·Git·SQLite 저장/재시작 검사를 통과했다.
macOS DMG, Windows EXE 생성과 설치·실행·제거는 해당 OS에서 검증해야 한다.
이 문서는 공개 출시나 지원 OS/CPU 전체의 검증 완료를 의미하지 않는다.

## 만들기

빌드 PC에 Node.js 24 이상, pnpm 10, Git을 준비하고 저장소 루트에서 실행한다.

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm check
```

| 빌드 환경 | 명령 | 생성 대상 |
| --- | --- | --- |
| Apple Silicon macOS | `pnpm desktop:package --arm64` | 개발용 DMG |
| Intel macOS | `pnpm desktop:package --x64` | 개발용 DMG |
| Windows x64 | `pnpm desktop:package --x64` | 사용자 단위 NSIS EXE |
| 각 OS의 앱 폴더 확인 | `pnpm desktop:package --dir` | 설치 파일 전 단계의 앱 폴더 |

기본 CPU는 빌드 PC의 CPU이며, Linux에서는 `--dir`만 허용한다. Linux에서 만든 폴더를
Windows/macOS에서 실행할 수 있다는 뜻이 아니다. Windows ARM64는 빌드 인수로 선택할 수 있으나
지원 확정/실기기 검증 전이며, Windows/WSL 실행부의 지원 범위와도 구분한다.

명령은 웹 화면을 먼저 빌드하고, `artifacts/desktop/v2-preview-*`의 새 폴더에 결과를 만든다.
기존 v1 설치 파일, 이전 빌드, 사용자 프로젝트는 덮어쓰거나 삭제하지 않는다.
패키징 도구가 pnpm을 하위 명령으로 사용하므로 위 pnpm 명령으로 실행한다.

Electron 패키징을 시작하기 전에 저장소와 임시 폴더가 있는 파일시스템의 여유 공간을 확인한다.
어느 쪽이든 2 GiB 미만이거나 확인에 실패하면 중단하며 이전 결과나 사용자 파일을 자동 삭제하지 않는다.
이는 최소 여유 공간 검사이며 빌드 중 다른 프로세스의 사용량이나 최종 설치 파일 크기까지 보장하지 않는다.

외부 인증서 환경 변수를 빌드 프로세스에서 제외하고 인증서 자동 탐색을 끈다.
macOS는 개발용 ad-hoc 서명만 사용하고 공증하지 않는다. Windows는 외부 인증서로 서명하지 않는다.
자동 업로드/공개 배포/자동 업데이트를 하지 않으며, 설치 후 자동 실행도 끈다.
공개 출시에는 별도의 서명·공증·업데이트 정책 및 사용자 승인이 필요하다.

## 패키지에 포함되는 내용

- Electron 런타임과 런타임이 제공하는 라이선스 고지.
- 데스크톱 진입점·제한된 preload·트레이 아이콘.
- v2 실행부 모듈, 빌드된 화면과 자산.

앱의 ASAR에는 허용한 파일만 들어간다. `.git`, `.orca`, 개발 데이터, DB, 인증 파일,
구버전 실행부, 테스트, 빌드 도구와 개발 의존성을 포함하지 않는다. 생성 후 실제 ASAR의 파일 목록,
현재 소스/자산과의 일치, 버전·진입점, 실행 파일의 보안 fuse를 검사하며 실패하면 성공으로 보고하지 않는다.

```bash
node scripts/verify-desktop.mjs <생성된 앱 폴더>
```

macOS에서는 `.app` 폴더, Windows에서는 `win-unpacked` 계열 폴더를 지정한다.
실행 파일은 앱을 Node로 실행하는 환경 변수, Node 환경 옵션, 디버거 인수 및 추가 file 프로토콜
권한을 비활성화한다. 렌더러 sandbox/contextIsolation은 그대로 유지한다.
이 검사는 설치된 앱의 실제 실행·계정 연결·전체 보안 검증을 대신하지 않는다.

Git·Codex CLI와 프로젝트의 개발 도구는 앱에 포함하지 않는다. 사용자가 선택한 실행 환경에
별도로 준비해야 한다. SSH/WSL 실행부에는 기존 요구처럼 Node.js 24 이상도 필요하다.
진단은 Electron 실행 파일을 Node로 재실행하지 않고 OS 기본 `echo` 명령으로 수행한다.
Windows에서는 시스템 `cmd.exe /d /c`의 고정 명령만 사용하며 AutoRun과 임의 본문 삽입을 사용하지 않는다.
[Codex 명령 실행 규약](https://learn.chatgpt.com/docs/app-server).

## 데이터와 제거

개발 실행/설치 파일 이름이 달라도 데스크톱의 기록 위치를 다음으로 고정한다.
별도 검사나 데이터 분리가 필요하면 Electron의 `--user-data-dir=<절대 경로>` 실행 인수를 사용할 수 있다.
지정한 폴더가 별도 프로필이 되며 기존 기록을 자동으로 복사하거나 옮기지 않는다.

| OS | v2 작업 기록 위치 |
| --- | --- |
| macOS | `~/Library/Application Support/Otter/v2` |
| Windows | `%APPDATA%/Otter/v2` |
| Linux 개발 검사 | Electron appData 아래 `Otter/v2` |

기존 브라우저 실행의 `.otter-v2` 및 개발 프리뷰 경로는 별도다. 이전 Electron 개발판의
패키지 이름 기반 데이터 폴더는 삭제하거나 자동 이관하지 않는다. 기존 기록이 있다면 실행부를
완전 종료한 상태에서 원본을 백업하고, 데이터 경로 전환을 별도로 확인해야 한다.

Windows 제거 설정은 앱 데이터를 삭제하지 않도록 한다. 사용자 저장소는 설치 폴더 외부에 둔다.
제거나 업데이트 전 **Otter 완전 종료**로 진행 중인 작업의 정리를 마쳐야 한다.
Windows 설치/제거의 실행 확인은 `apps/desktop/installer.nsh`로 교체했다. `Otter.exe`가 실행 중이거나
프로세스 조회가 실패하면 종료 안내 후 설치/제거를 중단한다. 무인 실행도 오류 코드 1618로 중단한다.
기본 설치 관리자의 강제 종료 경로는 사용하지 않으며 사용자에게 트레이에서 완전 종료하도록 요청한다.
조회는 이름 기준이므로 다른 Otter 설치까지 보수적으로 막을 수 있고, 검사 직후 앱이 다시 시작되는 경쟁을
잠금으로 차단하는 기능은 아니다. 실제 Windows에서의 설치·업데이트·제거 수용 검사는 남아 있다.
OS 강제 종료와 앱 폴더 안에 직접 보관한 파일의 보존도 보장하지 않는다.
직접 데이터 폴더를 삭제하는 동작이나 자동 데이터 청소는 제공하지 않는다.

```bash
node scripts/smoke-installer-guard.mjs
```

위 검사는 기존 electron-builder의 NSIS 도구·플러그인으로 작은 설치/제거 검사 스크립트를 각각 컴파일한다.
도구가 없으면 패키징 도구의 다운로드 경로를 사용한다. 실제 조회 호출과 중단 명령 포함, 기본 강제 종료
호출 제외를 컴파일 로그에서 확인한다. EXE는 실행하지 않으며 완성된 Windows 설치 파일 검사를 대신하지 않는다.
확장 방식은 [NSIS include 옵션](https://www.electron.build/v26/docs/nsis/#custom-nsis-script),
조회 결과에서 603만 부재로 인정하는 기준은 [nsProcess 반환 코드](https://nsis.sourceforge.io/NsProcess_plugin)를 따른다.

## 로컬 기록 백업

- Otter 메뉴의 **로컬 기록 백업…**은 프로젝트가 없어도 사용 가능하다. 프로젝트 설정에도 같은 동작을 제공한다.
  네이티브 범위 확인과 파일 저장 대화상자를 거치며, 렌더러가 임의 경로를 넘겨 쓰는 HTTP API는 만들지 않는다.
- 로컬 SQLite 전체의 사본이다. 원격 조회 캐시는 들어가지만 원격 실행부 DB, 실제 저장소/직원 작업 파일,
  계정 인증 파일, 미저장 입력은 제외한다. 사본은 비암호화 상태이며 기록에 들어간 비밀도 포함될 수 있다.
- SQLite 백업을 전용 임시 폴더에 생성하고 독립 단일 파일로 검증한다. 기존 대상 파일/링크에는 저장하지 않는다.
  SHA-256과 파일 동기화 확인 후 완료를 표시한다. POSIX는 0600 파일 권한을 사용하며 Windows ACL은 미검증이다.
  임시 폴더만 정리하고 사용자 원본/대상 파일은 자동 삭제하지 않는다. 실패 후 남은 파일은 완료된 백업이 아니다.
- 중복 백업과 종료 중 새 요청을 막는다. 이미 시작한 백업은 완전 종료에서 끝날 때까지 기다린 뒤 DB를 닫는다.
  대상 OS의 실제 네이티브 대화상자·디스크 부족·전원 차단 수용 검사는 별도로 남아 있다.
- 사본의 `otter.recordBackup` 표식은 실행용 DB로 여는 것을 거절하여 대기 업무의 우발적 실행을 막는다.
  자동 복원/업무 재개는 구현하지 않았다. 표식을 제거하거나 기존 DB에 덮어쓰는 수동 복원을 안내하지 않는다.
  저장소·원격 기록까지 포함한 백업 범위와 안전한 복원 절차는 후속 확정/구현 대상이다.

## 화면 오류와 종료 확인

- 최초 페이지 로드 실패 또는 렌더러 프로세스 종료를 감지하면 네이티브 복구 선택 창을 표시한다.
  화면만 다시 불러오기, 백그라운드 유지, 완전 종료를 선택할 수 있다. 화면 복구는 새 업무나 실행부를
  만들지 않으며, 저장하지 않은 입력의 복원을 보장하지 않는다. React 내부 오류 등 모든 빈 화면을
  감지하는 기능이나 시스템 강제 종료 복구를 뜻하지 않는다.
- 백그라운드 유지 후에는 트레이/메뉴의 사무실 열기로 다시 시도한다. 진행 중인 화면 로드는 합치고
  정상 창은 다시 표시만 하므로, 재열기 자체로 작성 화면을 불필요하게 새로 고치지 않는다.
- 시작 중 종료 요청은 초기화가 끝날 때까지 기다린 뒤 생성된 실행부를 정리한다. 실행부 생성 이후
  시작 오류도 동일한 종료 확인을 거친다. 종료에 실패하면 앱/기록/잠금을 강제로 제거하지 않고
  사용자가 상태 유지 또는 종료 재확인을 선택한다. 이미 종료를 시작한 뒤에는 네이티브 새 요청도 막는다.
- DB 열기·기록 초기화 실패는 원본을 보존하고 이번 시작의 연결/잠금을 정리한 뒤 실패로 종료한다.
  작업 기록 위치와 디스크·권한·백업 확인 안내를 표시하며 원시 DB/JSON 값은 노출하지 않는다.
  기존 실행부 잠금이나 소유권이 바뀐 잠금은 삭제하지 않는다. 손상된 DB의 자동 수리·초기화 기능은 아니다.
- 배포 명령의 상위 프로세스가 끝나도 추적한 POSIX 프로세스 그룹의 종료를 확인하지 못하면 완전 종료를
  보류하고 그룹 번호와 확인 안내를 표시한다. DB/잠금을 유지하며 확인 후 종료를 다시 시도할 수 있다.
  해당 그룹을 자동 강제 종료하거나 Windows/별도 세션/외부 서비스의 전체 종료를 보장하는 기능은 아니다.
- `pnpm --filter @otter/desktop test`는 제품의 실제 시작·이벤트·메뉴·종료 코드를 사용하되
  Electron 창과 대화상자는 대역으로 검사한다. 종료 실패 시 실제 임시 실행부의 HTTP/SQLite/잠금 유지와
  재시도 후 해제를 포함한다. 네이티브 GUI가 정상 실행됐다는 증거로 간주하지 않는다.

종료 흐름은 [Electron 앱 종료 이벤트](https://www.electronjs.org/docs/latest/api/app#event-before-quit),
화면 복구는 [페이지 로드](https://www.electronjs.org/docs/latest/api/web-contents#contentsloadurlurl-options) 및
[렌더러 종료 이벤트](https://www.electronjs.org/docs/latest/api/web-contents#event-render-process-gone)를 따른다.

## 대상 OS에서 남은 수용 검사

자동화 가능한 런타임/기본 창 검사는 다음 명령으로 실행한다.

```bash
pnpm desktop:runtime <생성된 resources/app.asar 경로>
pnpm desktop:smoke
```

- `desktop:runtime`은 개발용 Electron을 Node 모드로 실행해 **실제 패키지 안의 실행부**를 불러온다.
  화면/자산 제공, API 인증, 임시 Git 프로젝트, SQLite 데이터 재시작 보존, 원격 실행부 모듈 읽기를 검사한다.
  별도 손상 DB로 연속 시작 실패를 재현하여 원본 보존과 이번 시작 잠금 정리도 확인한다.
  실제 패키지의 기록 백업 모듈로 SQLite 사본 생성·덮어쓰기 거절·사본 실행 차단과 잠금 정리도 확인한다.
  모델 생성은 금지하며 사용자 데이터 대신 새 임시 폴더를 사용한다. 일반 Node만으로 통과시키지 않는다.
- `desktop:smoke`는 개발 런타임에서 실제 Electron 창/제한된 preload/설정 화면,
  창 닫기 후 유지/메뉴 재열기/완전 종료를 검사한다. 별도 임시 프로필을 사용하고
  `chromiumSandbox: true`를 명시한다. 자동화용 inspector는 개발 런타임에만 사용하며
  배포 실행 파일의 보안 fuse를 다시 켜지 않는다. 실제 폴더 선택 대화상자는 이 검사에 포함하지 않는다.
- Linux의 디스플레이 없는 검사 환경에서는 `xvfb-run -a pnpm desktop:smoke`를 사용할 수 있으나
  GTK와 정상적인 Chromium 샌드박스 지원은 여전히 필요하다. 샌드박스 해제를 통과 방법으로 사용하지 않는다.
- 현재 검사 호스트에서는 GTK 등의 패키지를 임시 폴더에 풀고 해당 검사 프로세스의 라이브러리 경로로만
  지정해 런타임 검사를 통과했다. 시스템 패키지나 권한 설정은 변경하지 않았다.
  GUI는 그 다음 SUID 샌드박스 설정 단계에서 중단됐으며 성공으로 취급하지 않는다.

Node 모드는 [Electron 공식 환경 변수](https://www.electronjs.org/docs/latest/api/environment-variables/),
GUI 검사의 샌드박스 옵션은 [Playwright Electron API](https://playwright.dev/docs/api/class-electron)를 따른다.
아래 네이티브/설치 수용 검사는 여전히 필요하다.

1. 새 사용자 환경에서 설치하고 시작 메뉴/Finder로 실행한다. 개발 저장소가 없는 PC에서도
   화면·트레이·폴더 선택·설정 저장이 동작하는지 확인한다.
2. Codex 준비 상태를 확인하고 기존 계정으로 실제 업무를 수행한다. GUI로 실행할 때의 CLI 탐색과
   로그인 상태, 시스템 샌드박스, 외부 IDE 연결을 검증한다.
3. Windows에서 WSL 프로젝트, macOS/Windows에서 실제 SSH 프로젝트의 폴더·실행·승인·재접속을 검사한다.
4. 창 닫기/재열기/완전 종료/재실행, 실행 중 종료 확인, 원격 실행 유지와 중복 실행 방지를 검사한다.
   초기 화면 로드 실패·렌더러 종료 시 복구 선택, 시작 도중 종료, 종료 실패 후 재확인도 검사한다.
5. 같은 앱 ID의 업데이트 및 제거/재설치 후 데이터 보존을 확인한다. 종료 미확인 상태에서 설치 관리자가
   작업을 강제 종료하지 않도록 하는 절차도 검증한다.
6. 공식 배포 전 저작권·자산/의존성 고지, 서명·공증, 지원 OS/CPU, 업데이트·백업 정책을 확정한다.

표준 패키징은 [electron-builder 파일 포함 규칙](https://www.electron.build/v26/docs/contents/)과
[NSIS 설치 옵션](https://www.electron.build/v26/docs/nsis/)을 사용한다.
