# 사용성 검토 — 2026-09-09

기존 프로젝트·Git·Work Unit·에이전트·세션·터미널 기능을 유지하면서, 기능을 찾고
오가고 이어서 쓰는 흐름을 개선한다. IDE로 전환하는 작업은 아니다.
코드 편집기·파일 저장 API·언어 서버·디버거·추가 에이전트 엔진은 추가하지 않는다.

## 비교와 진단

Otter 코드와 브라우저 사용 흐름을 아래 제품의 공식 문서에 설명된 패턴과 비교했다.
경쟁 제품을 직접 조작한 비교 실험이나 사용자 조사는 아니며, 기능 동등성을 주장하지 않는다.

## 확인할 사용 흐름

- 등록 목록이나 사이드바에서 프로젝트를 연다. 경로를 몰라도 폴더 선택을 찾을 수 있다.
  등록·해제의 의미는 그대로이며, 해제해도 실제 디렉토리나 파일을 삭제하지 않는다.
- 기존 워크플로를 진행하고 Work / History / Review 사이를 이동한다.
  에이전트 조작부는 같은 위치에 두고, 상세 결과는 필요할 때 펼친다.
- `@name`을 외우지 않고 수신 에이전트를 선택한다. 명시적인 `@name` 입력도 유지한다.
  전송 버튼을 눌러야 요청하며, 작업별 초안은 같은 탭의 화면 이동·새로고침 후 복원한다.
  전송 성공 후에만 초안을 비운다.
- 세션 목록·페이지·필터를 유지한 채 대화를 읽는다. 상세 화면의 기본 탭은 Conversation이다.
  필터는 현재 페이지에만 적용됨을 표시하고, 전체 내용 검색은 기존 Search에서 제공한다.
- 터미널을 숨겼다가 열어도 프로세스와 출력을 유지한다. 명시적 종료는 확인을 받는다.
  다른 프로젝트·워크트리·작업의 터미널은 각각 탭으로 유지한다.
- 새로고침 후 현재 위치를 복원한다. 브라우저 뒤로 가기와 맥락 이동 버튼을 제공한다.
  Alt+1/2/3/4로 Projects / Work Units / Sessions / Search를 연다.

## 범위와 남은 한계

- 브라우저 연결이 끊기거나 새로고침하면 터미널 프로세스는 기존처럼 종료된다.
  숨기기와 연결 종료는 다르다. 앱을 다시 열 때 셸이나 유료 에이전트를 자동 실행하지 않는다.
- 이번 작업은 첫 사용성 개선이다. 실제 다중 프로젝트 작업으로 추가 검증해야 한다.
  대량 목록 탐색, 키보드만 사용하는 대화상자 조작, 프로필 설정과 첫 사용 안내는 후속 점검 대상이다.
- 현재 위치와 미전송 초안은 해당 출처·브라우저 탭의 sessionStorage에 저장한다.
  별도 외부 서비스로 전송하지 않으며, 브라우저의 세션 복원 정책에 따라 탭 복원 시 다시 나타날 수 있다.
- 제공자 메타데이터, 저장소 내용, 브랜치 및 삭제 동작은 변경하지 않았다.
  최초 개선에서는 백엔드와 의존성 구성을 변경하지 않았다.

## 프로젝트 개요 후속 개선

- 작업 목록과 Workspace Map을 작은 두 영역으로 배치하고, 목록이 길어져도 높이를 제한한다.
- 워크트리의 경로·변경 파일·전체 커밋 해시는 선택한 경우에만 확인한다.
- 커밋 트리는 실제 부모 커밋 관계를 SVG 선으로 표시한다. 브랜치·태그 이름, 제목,
  짧은 해시와 날짜를 기본으로 보이고, 선택 시 작성자·전체 해시·부모 정보를 펼친다.
- [Git log 공식 문서](https://git-scm.com/docs/git-log)의 위상 순서와 부모 정보 형식을
  사용한다. 인증된 읽기 전용 `/api/projects/{id}/commits`를 추가했으며, 로컬에 있는
  참조와 HEAD를 조회한다. fetch·checkout·commit은 실행하지 않는다.
- 처음 50개를 표시하고 최대 200개까지 늘릴 수 있다. 그래프의 높이는 제한하고 내부에서
  스크롤한다. 원격 추적 참조는 마지막 fetch 기준이며 최신 원격 상태를 보장하지 않는다.
