# Otter v2 구현 기록

상태: 구현 진행 중. 요구사항의 축소 또는 MVP 완료 선언이 아니다.

## 결정

- React 화면을 재사용 가능한 기반으로 유지하고, 실행부는 Node.js 24 이상으로 새로 구현한다.
- 설치형 화면은 Electron을 사용한다. 로컬·WSL·SSH 실행부는 같은 Node 코드로 동작하도록 한다.
- 데이터는 Node 내장 SQLite에 저장한다. 기존 Otter DB와 별도 경로를 사용한다.
- Codex는 설치된 CLI의 App Server 표준입출력 프로토콜에 연결한다. 구독 인증 정보를 복사하거나 범용 API 키로 바꾸지 않는다.
- 배경·가구·직원 외형은 표현 계층이고, 직원 ID·역할·업무 상태는 실행 데이터다.
- 초기 기본값은 요구사항 8절의 제안을 사용한다. 사용자 검토 후 완료, 최대 동시 실행 2개, 재시도 한도 2회다.

공식 근거: [Codex App Server](https://learn.chatgpt.com/docs/app-server),
[인증](https://learn.chatgpt.com/docs/auth),
[Electron 보안](https://www.electronjs.org/docs/latest/tutorial/security),
[Node SQLite](https://nodejs.org/api/sqlite.html).
연동 스키마는 설치된 `codex-cli 0.153.4`의 생성 결과로 대조한다.

### 1차 종료 시 남았던 항목 — 최신 상태는 아래 2차 기록 참고

1. PM의 실제 업무 분해/배정/인계와 신규 직원 제안 승인. 말풍선을 임의 생성하지 않는다.
2. 대화 이어가기와 프로젝트 단체방/업무 스레드, 직원 간 메시지와 보고 분리.
3. 직원 설정 편집·파생·선택 업데이트 UI, 프로젝트별 조정과 공유 지식 승인.
4. 직원의 문서 변경 제안과 차이 검토, 저장소 지침 파일과의 충돌 처리.
5. 정책 강제·독립 검증·자동 완료 옵션. 현재 `untrusted` 승인 정책은 보수적인 연결
   단계이며, 사용자 정책을 모델 지침으로만 강제하는 구현을 완료로 인정하지 않는다.
6. SSH/WSL 실행부 배치·재연결·상태 동기화·전역 동시 실행 한도·안전한 종료.
7. Electron 환경별 검사와 macOS/Windows 설치 패키지. 실제 OS별 검증 없이 지원 완료
   표시를 하지 않는다.
8. 새 기능 연결 후 기존 비활성 Rust/Tauri/UI 소스와 v1 스크립트 정리.

현재 프리뷰는 결과를 작업 브랜치에 남긴다. 기본 브랜치 자동 통합이나 무인 운영을 검증한 상태가 아니다.

## 2차 구현 검증 — 2026-09-11

- PM 직접 위임, 실제 팀 조회/배정, 선행 업무 의존 관계와 Git 인계를 구현했다.
  PM은 결과 대기 중 실행 슬롯을 반납하고, 직원 결과가 모이면 같은 Codex 대화로 재개한다.
  업무 분해와 메시지는 모델이 실제 호출한 Otter 도구에서 생성하며, 연출용 대화를 넣지 않는다.
- 신규 직원 채용은 역할·모델·지침·이유를 제안하고 사용자 승인 뒤 생성/배정한다.
  문서 수정은 현재 버전과 변경안을 보관하며, 승인 전에 파일/문서를 덮어쓰지 않는다.
  승인 시 문서가 달라져 있으면 충돌로 거부한다.
- 직접 요청의 대화 이어가기, 프로젝트 대화와 직원 간 대화 필터, 업무/보고에서
  해당 대화로 이동, 실제 실행 중 직원에게 메시지 전달을 연결했다.
  실행 중이 아닌 수신자는 다음 실행에서 받으며 화면에 전달 상태를 표시한다.
- 직원 라이브러리 원본 편집, 프로젝트 전용 조정, 파생 직원 생성, 원본 차이의 선택
  업데이트 UI와 실제 저장 경로를 연결했다. 설정 변경은 다른 프로젝트에 자동 적용하지 않는다.
- 작업 결과는 전용 worktree에서 커밋하여 후속 직원/PM 작업 브랜치로 인계한다.
  기본 브랜치와 원격 저장소에는 자동 병합/푸시하지 않는다. 충돌은 해당 worktree에
  보존하며, 미해결 파일을 자동 스테이징하여 완료 처리하지 않는다.
- `pnpm check`, `pnpm build` 및 실행부 검사 8개, 사무실 UI 검사 1개 통과.
  PM 실행 한도 1에서의 슬롯 양보, 실제 Git 파일 인계, 충돌 보존/해결 후 재개,
  승인 전 미생성, 문서 충돌, 프로젝트 격리와 메시지 전달을 합성 제공자로 검증했다.
- `scripts/smoke-v2-codex.mjs --run --pm`: 실제 Codex PM → 개발자 → 리뷰어 → PM
  재개 → 사용자 검토 완료 통과. 개발 파일과 리뷰 결과가 최종 PM 브랜치로 인계됨을 검사했다.
  증거 디렉토리: `/tmp/otter-live-codex-HZOfTD`.
  앞선 `/tmp/otter-live-codex-3jjDTw` 검사는 테스트 허용 목록 밖의 Python 읽기 명령을
  요구해서 승인하지 않고 중단했다. 재검사는 정확한 `cat -- hello.txt` 읽기만 허용했다.
- `scripts/smoke-v2-ui.mjs`: 원본/프로젝트 설정 분리, 선택 업데이트, 직원 파생/배정,
  문서 저장/보관/복원까지 브라우저 검사 통과. 최신 스크린샷: `/tmp/otter-ui-smoke-Smvu0h`.

### 실행 제약과 남은 범위

- 동적 도구는 [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)의
  실험적 기능을 사용한다. 실제 검증한 CLI는 0.153.4이며 다른 버전 호환성을 가정하지 않는다.
- Codex 내부 하위 에이전트 기능과 공통 메모리는 해당 실행에서 비활성화한다.
  직원 생성 승인과 프로젝트 기억 분리는 Otter의 흐름을 거쳐야 한다.
- 한 목표의 배정은 32개, 한 실행의 직원 간 메시지는 32개로 제한하여 무한 분해/대화를 막는다.
  이는 임시 보호 한도다. 설정의 재시도 횟수를 이용한 안전한 자동 복구는 아직 미구현이다.
- 기존 배정 작업의 추가 요청은 상위 PM 목표에서 이어간다. 직원 간 메시지 전달은
  실행 생성/증설을 자동으로 유발하지 않는다.
- SSH/WSL, 초기 아이디어 인터뷰의 전용 진입 흐름, 저장소 지침 파일 동기화,
  승인된 공통 지식 공유, 전체 실행 권한 강제, 독립 검증/자동 완료, 네이티브 배포 검증은 남아 있다.
- 현재 증거는 부분 시나리오의 통과다. A-01~A-14 전체가 완료되었다고 판단하지 않는다.

## 3차 구현 검증 — 2026-09-11

- SSH/WSL 연결 명령, 원격 실행부 설치, 별도 Node 프로세스와 SSH 표준입출력 중계를 연결했다.
  SSH 호스트 키 검증·비대화형 인증을 강제하고 에이전트 전달/포트 포워딩을 사용하지 않는다.
  근거: [OpenSSH 클라이언트](https://man.openbsd.org/ssh),
  [서버 설정](https://man.openbsd.org/sshd_config). 새 통신 프레임워크 없이 Node 기본 모듈을 사용했다.
- 실행부의 HTTP는 원격 루프백에만 바인딩하고 개인 연결 파일의 토큰을 요구한다.
  원격 실행부에는 웹 화면/쿠키 자동 로그인을 제공하지 않으며, 토큰을 SSH 응답이나 UI에 보내지 않는다.
- 전체 실행 한도에서 원격 자리 수를 고정 예약한다. 연결 단절/앱 종료로 예약을 반환하지 않는다.
  현재 로컬 실행을 침범하는 예약/한도 축소를 거부하고, 로컬 큐는 남은 자리만 사용한다.
- 원격 환경의 프로젝트·업무·대화·문서는 해당 실행부에 저장한다. 앱은 명시한 환경으로 전달하며
  실패 시 로컬 실행으로 대체하지 않는다. 직원 설정만 재사용하고 프로젝트 대화는 가져오지 않는다.
- 요청 ID의 내용과 결과를 SQLite에 저장한다. 같은 요청은 결과를 재생하고, 진행 여부가
  불확실한 요청은 새로 중복 실행하지 않는다. 단일 프로젝트 회사의 환경 간 중복 생성도 차단한다.
- 환경 관리 화면, 로컬/원격 프로젝트 선택, 원격 폴더 탐색, 실행 환경 표시,
  연결 해제/재연결 및 오프라인 캐시 안내를 연결했다. 원격 선택 시 네이티브 로컬 폴더 창을 열지 않는다.
- `apps/worker/test/remote.test.mjs`: 별도 실행부 PID 유지, 중복 생성 방지, 토큰 미노출,
  원격 설정 배정/대화 격리/큐 예약, 연결 단절 중 합성 작업 완료 및 보고 복원 검사 통과.
  이 검사는 SSH 전송을 로컬 프로세스로 대체하며, Codex는 합성 제공자다.
- `node scripts/smoke-v2-ssh.mjs --run`: 실제 Linux OpenSSH로 임시 키 인증, 실행부 설치,
  Git 저장소 생성, 연결 단절/PID 유지, 재연결 및 재전송 검사 통과.
  첫 검사는 `/tmp` 상위 권한 때문에 `StrictModes`에 거부되어, 보호 설정을 끄지 않고
  무시 경로의 개인 검사 폴더로 옮긴 뒤 통과했다.
  최신 재검사 증거: `.otter-dev/ssh-smoke-5Yxroj`. 사용자의 SSH 설정/키나 서버 설정은 수정하지 않았다.
- 확장한 브라우저 검사: 기존 로컬 시나리오에 원격 환경 등록·폴더 탐색·직원 재사용·문서 저장,
  로컬 DB 격리·오프라인 캐시·재연결을 추가하여 통과했다.
  최신 재검사 스크린샷: `/tmp/otter-ui-smoke-zctUf8/environments.png`, `remote-offline.png`.
